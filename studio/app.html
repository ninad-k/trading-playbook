1Model

Pick the model that reads your books. Models marked offline run on this machine; the rest route through your ollama.com subscription. The difference that matters is not quality but context: a cloud model with a million-token window reads a whole book in one pass, where an 8 GB card can only be shown about twelve pages. The draft records which of the two happened.

2Dedup index

Two indexes, built together. The first fingerprints every extracted source text — that is what actually catches the same book under a different filename, and it is exact. The second embeds every note, used only to name the nearest notes by subject. Rebuild whenever the library grows.

3Upload books

Drop as many PDFs as you like. They are copied into studio/uploads/, which is git-ignored — the files themselves never reach the site or the repository.

Drop PDFs here, or click to choose

4What is actually new

Three passes: the same file (by checksum), the same title, then the same text — hashed word-shingles compared against every source held, which also catches an excerpt or a re-edition. Measured on this library, unrelated books share 0% of their shingles, so a hit here is not a guess.

5Draft notes

Drafts land in content/drafts/, not in the library. Each records exactly what the model was shown — the complete text, or the sampled pages — and is marked machine-drafted until you approve it. A draft read end to end is marked source_review: full; a sampled one is never marked full.

Roughly a minute a book on glm-5.2:cloud, reading it end to end.

6Review and publish

Why the review gate. Every note in this library was checked against its source by hand, and that is the only reason the site is worth reading. A small local model drafting from a sample of pages does not meet that bar. Read the draft, fix what is wrong, then approve — approval is what puts it in the library.
