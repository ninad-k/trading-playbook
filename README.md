# Trading Playbook

**Trading books, explained and connected.** By Ninad K.

Library snapshot, 6 September 2026: **582 parent notes, 151 method sub-pages, and 14 topic/glossary pages**. This resume added **148 parent notes**. All 733 saved source PDFs are accounted for: 582 have notes, 106 are duplicates, 41 are off-topic, and four are damaged. No eligible notes are missing. See the [completion report](data/resume_completion.md), [searchable index](docs/index.html), and [continuation plan](PLAN.md).

Reading coverage is separate from file presence: all 582 parent notes now record what was read — **228 full source reviews and 354 partial**, each naming the exact PDF pages inspected. No note is left without recorded coverage. Long-book samples and OCR limitations are disclosed on each affected page and in the [coverage inventory](docs/coverage.html). The live source directory was not reverified.

Structured study notes from a library of 733 trading and finance PDFs (forex, technical analysis, candlesticks, Elliott/Gann/Fibonacci, day and swing trading, mechanical systems, money management, psychology, options and derivatives, market microstructure research, and investing classics). The target is a page for every eligible readable document, major-book notes with method sub-pages, 13 topic syntheses and a glossary, connected through a searchable static site.

> Educational summaries only. Nothing here is financial advice. The notes paraphrase ideas and rules; they do not reproduce the books. Buy the ones you find useful.

## Tiers

- **A** — major books: deep notes (overview, thesis, key concepts, rules and setups, risk, psychology, chapter map, caveats, who should read it, related) plus one sub-page per self-contained system.
- **B** — everything else readable: concise page (summary, key points, actionable rules, caveats, who it is for).
- **C** — documented duplicates, off-topic titles, or damaged files. Duplicate landing pages point to canonical notes. Missing native text alone is not an exclusion: recovered scans use OCR.

## Build

```bash
python -m venv .venv && .venv/Scripts/pip install -r requirements.txt   # Windows
python scripts/01_fetch.py          # download PDFs (resumable)

python scripts/03_triage.py --apply data/tiers.json   # after review
python scripts/04_chunk.py <slug>   # what the note-writing agents read
python scripts/05_validate.py       # schema + reconciliation
python scripts/06_build_site.py     # -> docs/
python scripts/12_check_site.py     # local links, fragments, search and PDF inventory
python scripts/07_export_medium.py --all-books  # -> export/medium/ drafts
python scripts/09_resume_inventory.py
python scripts/13_completion_report.py
```

Open `docs/index.html` locally, or serve `docs/`.

## Publish

**Source names, not filenames.** The site never prints a raw source filename. `common.display_title()`
turns whatever the file was called into a readable book name, and it is used for the coverage table,
the exclusion lists and the duplicate landing pages.

**GitHub Pages:** `docs/` is the static output, with relative navigation, a `.nojekyll` marker and local search assets. The destination is `github.com/ninad-k/trading-playbook` — the configured `origin` remote — served at `https://ninad-k.github.io/trading-playbook/`. Two steps publish it: push `main`, then set Pages to *Deploy from a branch* / branch `main` / folder `/docs` in repository settings. The URL returns 404 until both are done. The source mirror `downloads/` is git-ignored and is never published.

**Medium:** `export/medium/` contains editable Markdown drafts, including source-coverage labels. Review them before posting. Drafts already point at `https://ninad-k.github.io/trading-playbook/`, which matches the repository above; pass `--site` only if the public URL changes.

**Notion:** payload generation exists for a "Trading Playbook" page tree (Books database + Topics + Index). `data/notion_ids.json` currently records one synced book page; a complete mirror has not been verified. Confirm the destination before syncing more pages. Stored IDs allow updates without duplicating pages.

**OCR recovery:** `scripts/10_recover_scans.py` preserves old extraction and records exact PDF-page coverage. Job JSON can select `engine: tesseract` using PyMuPDF and the official English model from `tesseract-ocr/tessdata_fast`, stored locally as `downloads/tessdata/eng.traineddata`; `rotation: 180` handles inverted scans. RapidOCR remains available as the original optional backend. Saved recovery jobs and review decisions are in `data/resume_assignments/`.

## Manual Trader

`content/manual/` holds a nine-stage course, built to `docs/manual/` with previous/next links and a
progress rail so it reads as a sequence rather than as more reference pages. It is deliberately
self-contained: `05_validate.py` rejects any `[[wiki-link]]` in a lesson, because sending a reader off
to the library mid-lesson is what the course exists to avoid.

Lessons carry `stage`, `title`, `slug`, `goal` and optional `builds_on` / `diagram`, and must contain
the sections *What you will be able to do*, *The lesson*, *Worked example*, *Practice* and *Self-check*.
The validator also checks that stages are contiguous from 1 and that `builds_on` only ever points
backwards.

## Figures

`scripts/16_make_diagrams.py` and `scripts/17_course_diagrams.py` generate 18 schematic SVGs into
`content/diagrams/`. They are inlined at
build time — theme-aware, no external requests, readable without the site stylesheet. Each leads its
topic page, and 23 book notes attach one through a `diagram:` frontmatter key. The index and coverage
pages carry bar charts generated from the live counts, so they cannot drift from the data.

Figures are schematic. They illustrate a generic concept and are not traced from any book's artwork;
none of them asserts a price, a parameter or a result.

## Book Studio (local only)

`studio/` is a page for adding books to the library with a local Ollama model. It is not part of the
published site, binds to loopback only, and talks to nothing but `http://localhost:11434` and this
repository's own files.

```bash
python studio/server.py        # then open http://127.0.0.1:8799
```

Drop in as many PDFs as you like. Each one goes through three duplicate checks, then — if it is new —
a model drafts a note from it.

**Duplicate detection.** Checksum, then normalised title, then text overlap. The third pass hashes
8-word shingles of the source text and compares them against every text held, by Jaccard and by
containment, so it catches the same book under a different filename and an excerpt lifted from a
longer work. It was calibrated against the 106 duplicate pairs the manifest already knew about:
duplicates score 0.80–1.00, unrelated books score **0.000**.

An earlier version compared note embeddings instead. That was measured and thrown out — two
*different* trading books score a median 0.85 against each other, higher than some real duplicates,
because they all read like "a trading book about charts" to a sentence embedder. Embeddings still run,
but only to name the nearest notes by subject and rank which sampled pages sit furthest from anything
held. Both are advisory; neither decides a verdict.

**Drafting.** Every model call is constrained to a JSON schema through Ollama's `format` parameter, so
a small local model cannot ramble, cannot omit a section, and cannot invent a category — the enum only
contains the library's real ones. The Markdown is assembled from the returned fields; the model never
writes the page. A draft records exactly which pages the model was shown, and a mechanical check flags
any passage that looks quoted rather than paraphrased.

**The review gate.** Drafts land in `content/drafts/`, which is git-ignored, and carry
`draft_status: unreviewed`. Approving one is what moves it into `content/books/`, adds its manifest row,
and feeds its text back into the dedup corpus. Nothing a model writes reaches the library unread.

**Which model.** Measured on this machine (RTX 5070 Laptop, 8 GB VRAM) by drafting the same three
books with each candidate and scoring the result: did it pick the right category, how many of the
book's rules did it actually extract, and how often did it quote instead of paraphrasing.

| model | offline | avg s/book | category | rules found | quote flags |
|---|---|---:|---:|---:|---:|
| **qwen3.5:9b** | **yes** | 48 | **3/3** | **17–22** | 0–1 |
| qwen3:4b | yes | 18 | 3/3 | 11–18 | 1–2 |
| qwen3.5:4b | yes | 25 | 1/3 | 11 | 1 |
| qwen3.5:cloud (397B) | no | 43 | 3/3 | 20 | 0 |
| glm-5.2:cloud (756B) | no | 34 | 3/3 | 19 | 0 |

`qwen3.5:9b` is the default: it matches the 397B cloud model on every measure while running entirely
on the card. Ranges reflect run-to-run variance at temperature 0.15. `qwen3.5:4b` is a regression on
this task and `gemma4:12b` (7.6 GB) does not leave room for a usable context window.

Two settings matter more than they look. Ollama's default context is **4096 tokens**, which silently
truncates a book sample — `NUM_CTX` is set to 8192, which holds the sample and keeps a 9B model on the
GPU where 16384 spills to CPU. And the sample is budgeted by total characters and split evenly across
the chosen pages, so the coverage line on a draft states what the model was really shown.

**Cloud models need a fallback.** Ollama enforces `format` in the local inference engine, so a
cloud-routed model never sees the grammar and returns Markdown instead of JSON — every cloud draft
failed outright until `ask()` learned to retry, asking for the same schema in words. Cloud tags work
through the local daemon once the desktop app is signed in; an `OLLAMA_API_KEY` in a git-ignored `.env`
at the repository root is only needed to reach `ollama.com` directly.

Embeddings use `nomic-embed-text`. Cloud-routed models appear in the picker labelled as not offline.

## Content rules

- Paraphrase only. No verbatim passages, no chapter reproduction, no quote collections.
- No PDFs are hosted and the public site never links to the source mirror.
- Concrete beats vague: where a book gives numbers (lookbacks, stop distances, risk per trade), the notes keep them.
- Dated material is flagged in *Caveats*.
